# محتوى «الأذكار والرقية»

الأذكار اليومية بأنواعها، الرقية والأدعية بتصنيفاتها، الأعمال ذات الأجور، وقبسات
السيرة: كلها في ملف واحد، `zad.json`، وتُنشر **بلا إصدار جديد للتطبيق**.

```bash
node tool/zad/publish.mjs             # يفحص zad.json، وإن تغيّر ينشره
node tool/zad/publish.mjs --dry-run   # يفحص فقط
```

## كيف يصل إلى المستخدم

- نسخة من `zad.json` مضمَّنة في كل إصدار (`lib/data/zad_seed.dart`): التبويب يعمل من
  أول تشغيل بلا إنترنت.
- عند فتح التبويب (مرة كل بضع ساعات) أو السحب للتحديث، يسأل التطبيق Supabase: «هل من
  مراجعة أحدث مما عندي؟». لا ⇐ لا يُنزَّل شيء. نعم ⇐ تُنزَّل الحزمة **مرة واحدة**
  وتُحفظ في ملف على الجهاز، ومنه تُقرأ بعدها دائماً، بلا إنترنت.
- حزمة معطوبة لا تُعرض ولا تُحفظ؛ يبقى عند المستخدم ما كان.

لا زر تنزيل ولا انتظار: الحزمة كلها نحو 30KB.

## التعديل

عدّل `zad.json` ثم شغّل `publish.mjs`. هو يرفع `rev` وحده حين يتغيّر المحتوى، ويحدّث
النسخة المضمَّنة، ثم يقرأ المنشور بالمفتاح العام (كما يقرؤه التطبيق) ويتأكد أنه مطابق.
التزم بعدها بـ `zad.json` و`lib/data/zad_seed.dart` في git.

| القسم | ما يُضاف أو يُعدَّل |
|---|---|
| `athkar` | أنواع الأذكار. كل نوع: `id`، `title` (نص الزر)، `items`. الذكر: `text`، `virtue` (اختياري)، `count` |
| `duaCategories` | تصنيفات الأدعية: `id`، `title` (نص الزر)، `name` (الاسم على البطاقة، اختياري) |
| `duas` | `id`، `category` (معرّف تصنيف موجود)، `title`، `text`، `source`، `instruction` |
| `rewards` | `id`، `category`، `title`، `hadith`، `source`، `reward`، `tip` |
| `pearls` | `id`، `title`، `topic`، `story`، `source`، `lesson` |

- **نوع ذكر جديد** (أذكار السفر مثلاً): أضف عنصراً إلى `athkar`. زره وأذكاره يظهران في
  التطبيق بلا تعديل في الكود. كذلك تصنيف أدعية جديد في `duaCategories`.
- المعرّفات (`id`) لا تتكرر داخل قسمها، ولا يُغيَّر معرّف منشور.
- أسماء الله الحسنى ليست هنا: ثابتة في `lib/services/allah_names_full_data.dart`.
- النصوص شرعية: تُنقل من مصدرها بضبطها وتخريجها، ولا تُؤلَّف ولا تُلخَّص.

## الصلاحيات

القراءة عامة (جدول `content_packs`، الصف `zad`). الكتابة تحتاج رمز الاستيراد نفسه الذي
تستعمله المكتبة (`tool/library/.ingest-token`، خارج git).

## حدود

التطبيق يفهم `schema: 1`. إضافة حقل جديد لا يكسر الإصدارات المنشورة (تتجاهله)، لكن
تغيير معنى حقل أو حذف حقل مطلوب يكسرها: حينها تُنشر الحزمة الجديدة بمفتاح آخر
ويبقى الصف `zad` للإصدارات القديمة.
